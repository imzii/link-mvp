# LINK MVP

> 생각은 자유롭게, 협업은 유기적으로.
> AI보다 먼저 우리 생각부터: 대학생 팀플 회의를 **IN → SYNC → MATCH → UP** 순서로 진행하는 웹 툴

창의적기획과문제해결 2조 팀 프로젝트의 시연용 MVP입니다. 서버 없이 `index.html` 파일 하나로 동작하며, GitHub Pages에 그대로 올리면 됩니다.

## 써 보기

1. 첫 화면에서 **데모 데이터로 바로 체험**을 누르면 가상 팀원 5명이 아이디어를 제출한 상태에서 시작합니다.
2. 실제로 쓸 때는 진행자가 **새 회의 세션 만들기**를 누르고, 참여 링크를 팀 카톡방에 올립니다.
3. 팀원은 링크를 열어 카드를 쓰고, 화면에 나온 **제출 코드**를 카톡방에 붙여 넣습니다. 앱 설치나 가입은 필요 없습니다.
4. 진행자가 코드를 모아 붙여 넣고 **동시 공개**를 누르면 다음 단계로 넘어갑니다.

## 단계별 기능

| 단계 | AI 상태 | 기능 |
| --- | --- | --- |
| LINK IN | 꺼짐 | 블라인드 카드(아이디어 + 근거 한 줄), 숙고 타이머, 카드 수 게이지, 전원 최소 N장 제출 시 동시 익명 공개, 희망 역할 블라인드 제출 |
| LINK SYNC | 질문만 → 반론 | 비슷한 카드 묶기(원문 보존), **언더독 순서**(드문 의견부터 공개), 통과형 기명 체크리스트 5종(PPCo 순서), 강제연결 질문, 회의 준비 화면(설명 기회 / 쟁점 / 연결 후보), **AI 빨간 펜**(현실 연결·가치·창의적 변수 검증), 재반박, 투표, 70% 쏠림 시 악마의 대변인 |
| LINK MATCH | 추천 | 희망 역할 동시 공개, 희망과 부담을 고려한 역할 추천, 팀이 최종 조정 |
| LINK UP | 기록 | 생각 출처, 아이디어 진화 기록, 빨간 펜 기록, **기여 기록**(낸 아이디어 / 검토 참여 / 투표 / 역할), Notion용 마크다운 복사, PDF 저장(교수자 제출용), JSON 백업 |

## GitHub Pages 배포

1. GitHub에서 새 저장소를 만듭니다. 예: `link-mvp`, Public
2. 이 폴더의 `index.html`과 `README.md`를 올립니다. 웹에서 **Add file → Upload files**로 올려도 됩니다.
3. 저장소에서 **Settings → Pages → Build and deployment**로 갑니다. Source는 `Deploy from a branch`, Branch는 `main` / `/ (root)`로 고르고 Save를 누릅니다.
4. 1~2분 뒤 `https://<아이디>.github.io/link-mvp/`에서 열립니다.

## MVP의 한계 (발표 때 솔직하게)

- **서버가 없습니다.** 진행자 화면의 데이터는 진행자 브라우저(localStorage)에만 저장됩니다. 팀원 제출은 카톡으로 코드를 주고받는 방식으로 대신했습니다.
- **'AI'는 규칙 기반입니다.** 묶기는 글자 유사도, 질문과 반론은 템플릿입니다. 실제 서비스에서는 LLM이 카드 내용을 읽고 생성합니다(API 키가 필요해 정적 페이지에는 넣지 않음).
- **익명성이 완전하지 않습니다.** 제출 코드 안에 이름이 들어 있어, 기술적으로는 해독할 수 있습니다. 화면에는 작성자를 표시하지 않습니다. 실제 서비스에서는 서버가 이름과 카드를 분리해 저장합니다.
